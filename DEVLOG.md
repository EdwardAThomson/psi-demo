# Development Log

## 2026-07-27

Ported the security fixes and protocol redesign from the C++ implementation (Private-Set-Intersection PRs #3 and #4) back into this JS demo. The big one was a discrete log break in hash-to-group: elements were mapped as H(x)*G on P-256, so every mapped point had a publicly known discrete log, and a single protocol transcript let a participant recover the counterparty's per-element keys offline and enumerate their entire set. The protocol core now derives group elements via SHA-512 into RFC 9496 ristretto255 element derivation (the libsodium from_hash construction, built on @noble/curves and @noble/hashes). Two further protocol changes landed alongside: message payloads no longer carry plaintext grid positions (only fixed 32-byte values, correlated by index), and the trial-decryption path was removed entirely in favor of BLAKE3 membership tags, making finalisation O(A) instead of O(A*B) and closing a ciphertext length side channel. This is a breaking wire-format change. The refactor also extracted a shared protocol core (src/psiCore.mjs) used by the main thread, the worker, and a new node self-test that asserts no input element ever appears in a serialized message, and dropped five now-unused crypto dependencies. Follow-up commits swept the docs of leftover encrypt/decrypt terminology from the classical scheme and added a README note pointing readers at the C++ repo as the actively developed implementation, with this repo kept in protocol parity as the browser-native demo.

**Decisions & notes:** Threat model is now stated explicitly: private against honest-but-curious participants; a malicious participant can still probe membership with fabricated inputs. Remaining "encryption" references in the explainer are deliberate, describing the classical scheme for contrast. Tag derivation uses BLAKE3 in derive-key mode with context "PSI-membership-tag-v1".
